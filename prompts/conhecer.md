Você vai escrever a BASE DE CONHECIMENTO deste projeto para uma fábrica de software autônoma. Todos os agentes da fábrica (triagem, investigação, PO, arquiteto, devs, revisor, QA) vão ler este documento antes de trabalhar, sem nenhum humano por perto para tirar dúvidas.

Estude o repositório (somente leitura): README, CLAUDE.md, package.json/manifestos, estrutura de pastas, código principal, testes, CI.

Escreva um documento Markdown CONCISO (no máximo ~150 linhas) com:

1. **O que é o produto** — para quem, qual problema resolve, principais funcionalidades.
2. **Stack e arquitetura** — linguagens, frameworks, banco, serviços externos; como as partes se conectam.
3. **Mapa do código** — pastas/módulos importantes e o que cada um faz.
4. **Convenções** — estilo, padrões de nomes, como erros são tratados, idioma do código.
5. **Como testar** — comandos, onde ficam os testes, padrão dos testes existentes.
6. **Zonas de risco** — partes sensíveis (pagamento, auth, dados, migrações) que exigem cuidado extra.
7. **Glossário** — termos do domínio.

Só afirme o que você verificou no código. Responda APENAS com o Markdown do documento.
